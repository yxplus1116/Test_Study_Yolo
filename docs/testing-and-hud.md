# 图片测试、鼠标标定与调试窗口

当前类别名称统一为 **头部 HEAD C1** 和 **身体 BODY C0**。菜单原来的“人物识别”只是类别 0 的旧称，已改为“身体识别”，没有新增类别，也没有修改模型或目标选择规则。

## 用图片可以测试什么

**图片可以验证检测、目标选择和连续关联，但当前控制方式不能用来验证“桌面光标最终停在图片上的目标处”。**

当前控制量来自 `选中目标的控制点 − 采集画面中心`。蓝色十字表示这个画面中心，与桌面鼠标箭头的位置无关。鼠标输出也是相对移动；主检测循环没有读取当前光标坐标来计算误差。

例如屏幕上的目标一直位于采集中心右侧 80 像素，移动桌面光标并不会改变图片位置，下一帧误差仍是向右 80 像素。因此，保持输出条件成立时，光标可能继续向右移动，即使已经经过图片中的目标。调整标定系数只改变移动量，不能把这个参考点变成鼠标位置。

若要让桌面光标最终停到静态图片上的目标，需要单独的桌面光标模式，使用 `目标在屏幕上的坐标 − 当前光标坐标`，并持续反馈。当前菜单还没有这个模式。当前模式要验证完整控制收敛，需要自己的测试场景能随鼠标相对移动改变画面中的目标偏移，使目标逐步靠近蓝色十字；仅让图片保持静止不能验证这一点。

### 先验证识别与目标选择

1. 菜单选 **5**，打开一张模型确实能识别的图片。此模式不输出真实鼠标移动，默认显示 20 秒。
2. 用 **↑** 选择头部、**↓** 选择身体。
3. 查看黄色目标框、红色控制点，以及顶部 `SELECTED HEAD C1 ...%` 或 `SELECTED BODY C0 ...%`。绿色框是同类其他候选，灰色框是其他类别。
4. 菜单选 **11 → 3** 可打开最后识别图。只对同一张图片重复推理能检查选择稳定性，不能证明运动、遮挡时也能跟踪稳定。

### 再验证实时画面中的关联与丢失

1. 使用其他图片查看器打开图片，将待测目标放进所选显示器的中央 `416×416` 区域（或菜单 9 设置的尺寸）。
2. 把本项目菜单和调试窗口移到这个区域以外。程序会采到菜单和其他遮挡窗口；调试窗口置顶并不意味着它会自动从采集中排除。
3. 菜单选 **1** 或 **2**，慢慢拖动图片窗口，观察黄色框和红圈能否继续对应同一个目标。
4. 移开目标或遮挡它，应看到输出停止、红圈清除；重新出现时应按跟踪或重新选择规则恢复。快速大幅拖动可能使新旧框重叠不足，触发重新选择。

上述步骤不需要菜单 8 标定，也不需要开启菜单 3/4。菜单 3/4 可验证有条件的鼠标相对输出，但在静止图片上观察光标移动，不能当作“移动到目标后自动停住”的通过标准。

## 菜单 8：桌面鼠标标定

它测量的是：**程序发送一定鼠标移动单位，Windows 桌面光标实际移动了多少物理像素。** 用这个结果修正控制输出的 X/Y 比例，减少“一个输入单位直接当成一个屏幕像素”的误差。

实际流程：

1. 选择 8 后有 2 秒准备时间，将光标放在离屏幕边缘至少 128 像素的位置，保持不动。
2. 程序发送 X 方向 `+16、−16` 输入单位，再发送 Y 方向 `+16、−16`，每次检查桌面光标位置。
3. 检查往返位置与横纵方向是否符合预期，通过后保存 `config/calibration.yml`，下次运行自动读取。
4. ESC 或菜单 10 可以取消。取消或异常时不会保证把光标恢复到原点；完整成功测量会检查其已回到原点附近。

例如本机此前测试中，16 个输入单位对应约 21 个物理像素，得到约 `16÷21=0.762 输入单位/像素`。这个比例是本机当时的测量结果，Windows 鼠标速度或加速设置改变后程序会忽略旧标定，需重新测量。

标定不会提高识别置信度，不会更换目标，也不会使静态图片上的光标自动收敛。Windows 开启加速时，它只是该测量幅度下的局部估计；目标应用的原始输入、视角变化和内部灵敏度仍需单独验证。

## 调试窗口逐项解释

| 显示项 | 含义 |
|---|---|
| `HEAD C1` / `BODY C0` | 当前参与目标选择的类别，分别为头部 / 身体 |
| `DETECTION ONLY` | 当前只检测和记录，不允许真实鼠标输出 |
| `INPUT ENABLED` | 已允许真实输出；仍需有效目标、按住左/右键等条件满足 |
| `GPU: NVIDIA GeForce RTX 3060 Ti` | 执行 TensorRT 模型推理的显卡 |
| `capture: gdi / dxgi` | 屏幕采集方式；`image / video` 则是离线文件输入 |
| `No detections above confidence threshold` | 没有通过检测阈值的有效框，默认阈值为 50% |
| `No HEAD C1 candidate` / `No BODY C0 candidate` | 有其他类别检测框，但当前类别没有合格候选 |
| `SELECTED HEAD C1 79%` | 当前选中的具体目标及其检测分数；对应黄色框和红圈 |
| `IoU match pending / reacquiring` | 当前框未通过与旧目标的关联检查，输出已停止，等待后续关联或重新选择 |
| `DRY RUN - mouse output OFF` | 实际鼠标输出关闭；即使出现红圈也不会移动鼠标 |
| `WAIT - hold LEFT or RIGHT mouse button` | 等待按住鼠标左键或右键 |
| `WAIT - release the direction key` | 等待松开暂停/切换类别相关方向键，防止切换过程中输出 |
| `OFF - measurement older than allowed age` | 目标测量已超过允许年龄，默认 100 毫秒，不再据此输出 |
| `IDLE - target is in the center dead zone` | 目标控制点已落在画面中心死区内，默认 X/Y 偏移均不超过 0.75 像素 |
| `ELIGIBLE` | 预览检查时满足输出条件；实际输出线程还会检查，所以不等于本帧一定发送了移动 |
| `PAUSED` | 识别已暂停；按右方向键恢复 |
| `Waiting for a NEW frame` | 采集暂时没有新帧，旧测量不会继续授权移动 |
| `Capture unavailable` | 采集当前不可用，程序会尝试恢复；无有效目标输出 |
| `Boxes: 0` | 本帧所有类别的有效检测框总数，经过阈值筛选与同类去重 |
| `candidates: 0` | 当前类别符合条件的候选框数，不代表已锁定目标数 |
| `lost: 5/5` | 连续有效检测帧未匹配的计数已达到上限 5；达到上限后清除旧身份。没有目标的启动阶段也可能出现，不代表曾经检测到 5 个目标 |
| `sent: 0` | 本次运行中被 Windows `SendInput` 接受的移动调用累计次数，不是像素数；也不保证目标应用实际响应 |
| `Loop FPS: 36.3` | 最近约一秒报告区间的成功处理帧率，包含整个应用循环的开销 |
| `avg: 44.9` | 本次采集/处理循环启动以来的累计平均帧率，不包含此前加载或构建引擎的时间 |
| `GPU: 6.50 ms` | 最近处理帧的 GPU 推理计时间隔；不含 CPU 预处理、传输和窗口显示等独立阶段 |
| `capture: 5.79 ms` | 最近处理帧的采集耗时；不是整帧总耗时，也不是平均值 |
| 蓝色十字 | 当前采集画面的中心，控制误差的参考点，不是鼠标箭头 |
| 底部快捷键 | ↑头部、↓身体、←暂停、→恢复、ESC 退出当前任务 |

菜单里的 `PID` 是 Windows 进程编号，用来识别正在运行的程序，不是控制算法的 PID 增益。`显示器 0` 是被采集的显示器编号；`中心区域 416×416` 是中央裁剪尺寸，不是模型输入尺寸（当前模型输入为 640×640）。菜单显示“下次实时采集”的设置在下次启动任务时生效，不代表正在运行的任务已经切换。

用户所示截图中，采集区域里主要是蓝色菜单窗口。因此出现 `Boxes: 0`、`candidates: 0`、`lost: 5/5` 是符合当前画面的；同时 `DETECTION ONLY` 和 `DRY RUN` 表明鼠标输出关闭。这张状态图没有显示出“正在锁定目标但不移动”的情况。
