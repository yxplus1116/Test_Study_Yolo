# TestStudyYolo：本机视觉检测与控制实验

Windows / C++17 / OpenCV 4.10 / CUDA 12.6 / TensorRT 10.6。当前应用采用单帧检测、带 IoU 门限的目标关联，以及单一鼠标输出线程。默认仅显示识别结果并记录控制量。

本机已经完成依赖安装、Release 编译、引擎生成、模型对照与运行测试。日常使用只需双击根目录 **[start.cmd](D:/Projects/Test_Study_Yolo/start.cmd)**，在中文菜单中输入编号并按回车。菜单始终可以接受新的选择，检测日志自动保存，不会淹没输入提示。

启动另一项检测或性能测试时，会先正常停止旧任务。关闭菜单窗口也会通知它启动的程序退出；直接通过其他终端启动的实例需要在原窗口退出。回车可刷新菜单状态。默认采集为 GDI、显示器 0、中央 `416×416` 区域；设置保存在 `.local/menu-settings.json`。

调试预览窗口默认置顶，普通应用窗口不会遮住它；置顶不会每帧抢键盘焦点。其他置顶窗口、独占全屏或系统安全桌面不属于普通窗口遮挡的保证范围。

选择 **1** 可以测试你截图中的头部类别。选择 **3** 才会允许实际鼠标输出；还需要目标有效、测量未过期、识别处于启用状态且按住左键或右键。红圈只表示当前选中的控制点。控制误差是“目标到采集画面中心的偏移”，不是“目标到桌面光标的偏移”，静态图片不会因为光标移动而自动消除这个误差。

初次使用时，图片测试步骤、菜单 8 的标定用途及预览各字段的中文解释见 **[测试与调试窗口说明](D:/Projects/Test_Study_Yolo/docs/testing-and-hud.md)**，也可从菜单 `11 → 4` 打开本说明后进入该链接。

遇到“有红圈、sent 增加但目标应用不响应”，见 **[鼠标输入失效排查](D:/Projects/Test_Study_Yolo/docs/input-troubleshooting.md)**（菜单 `11 → 6`）。新版自动记录发送尝试/结果、前台进程、双方权限级别与光标状态；成功计数只表示 Windows 接受，不代表目标应用响应。

## 画面中的框、红圈和数字

- 旧版 `1:0.78` 表示 **类别 1、置信度 0.78（78%）**。新版显示为 `HEAD C1 78%`；类别 0 显示为 `BODY C0`。置信度是模型分数，不是准确率保证。
- 所有通过检测阈值与去重的框都会显示，但只有当前选择的类别能进入目标跟踪。旧命令默认选择类别 0，因此只有 `1:0.78` 的头部框时，可能没有任何可选目标。
- 头部模式也可能看到 `BODY C0`：模型同时检测两类，模式决定哪一类参与控制，不决定模型只输出哪一类。头框和身体框可以同时覆盖同一个人；去重只比较同类框。
- **黄色粗框**是当前选中目标，**绿色框**是当前类别的其他候选，**灰色框**是其他类别。顶部 `SELECTED HEAD C1 60%` 明确给出选中目标本身的分数。框旁标签会避开已有文字；拥挤时略去放不下的标签，顶部所选目标信息仍保留。
- 初次选择先筛选类别及置信度（默认至少 50%），再按“到画面中心的归一化距离 − 0.25 × 置信度”取最小值。持续跟踪时优先关联上一目标：从 IoU 至少 0.2 的同类候选中选择 IoU 最大的框。
- 没有合格关联就立即停止该次输出；连续丢失达到 5 帧后清除旧身份，下一个有效帧重新选择。高置信度也可能因类别不符或 IoU 不够而没有红圈。
- 红圈代表选中的控制点：类别 0 位于框高约 35% 处，类别 1 位于框中心；蓝色十字是采集画面中心。暂停、没有新帧或采集失败时，旧红圈会清除。

预览顶部会说明当前状态：`No BODY C0 candidate` 为当前类别没有候选，`IoU match pending` 为关联失配，`DRY RUN` 为鼠标输出关闭，`hold LEFT or RIGHT` 为等待按住鼠标按钮，`IDLE` 为目标位于中心死区。`ELIGIBLE` 仅表示满足预览检查条件，`sent` 是实际被 `SendInput` 接受的调用次数；这不保证目标应用已经按相同方式响应。

例如在默认 `416×416` 采集区域里，两个人的头框分别为：A 置信度 79%、框中心离画面中心 100 像素；B 置信度 60%、距离 20 像素。画面的半对角线约为 294.16 像素，因此 A 的排序值约为 `100/294.16 − 0.25×0.79 = 0.142`，B 约为 `20/294.16 − 0.25×0.60 = −0.082`。B 的值更小，首次会选 B；置信度更高并不自动获胜。这只是规则示例，不是对某张截图距离的测量。已有锁定时，优先延续 IoU 最大的合格旧目标，避免在相邻人物之间反复跳转。

## GPU 与帧率

本机使用 **RTX 3060 Ti + TensorRT GPU 推理**。本次顺序实测：纯模型约 **1028 FPS**，GDI 关闭预览约 **87 FPS**，DXGI 关闭预览约 **128 FPS**，GDI 显示预览约 **46 FPS**。日志中的 `fps` 包含采集、CPU 预处理、数据传输、推理、后处理和显示等开销；原来的约 51 FPS 是完整流程的结果，不是 GPU 单独运行模型的速度。

菜单 **7** 可以自行复测，预览顶部和日志也新增 GPU 与采集耗时。200 FPS 的完整流程需要每帧全部工作少于 5 ms，当前完整流程尚未达到。详细测量范围、逐阶段耗时及原始记录见 **[性能说明](D:/Projects/Test_Study_Yolo/docs/performance-explained.md)**。

DXGI 会等待桌面新画面，因此静止桌面的计数可能很低：后来菜单整组测试中约为 3.74 FPS、235 次空采样、0 次采集错误。GDI 则会持续采样静态画面。比较采集后端时需要同时看内容更新情况与空采样数量。

## 脚本职责与手动命令

下面的脚本仍作为菜单的内部工具或开发入口保留，日常不需要逐个运行。

| 文件 | 职责 |
|---|---|
| `start.cmd` | 统一入口：双击打开中文菜单；显式附带参数时转交 CLI |
| `scripts/menu.ps1` | 菜单、文件选择、设置、性能对比与结果查看 |
| `scripts/menu-session.ps1` / `menu-watchdog.ps1` | 菜单内部的进程管理与菜单关闭后的退出通知 |
| `scripts/run.ps1` | 前台命令行入口，设置依赖路径并运行程序；运行中显示日志，不是可输入功能编号的菜单 |
| `scripts/start-preview.ps1` / `stop.ps1` | 兼容原来的独立预览启动 / 停止方式 |
| `scripts/install.ps1` / `cuda-packages.json` | 安装本地依赖 / 固定下载地址与校验值 |
| `scripts/build.ps1` | 编译、核心测试并更新 `dist` 中的程序 |
| `scripts/validate_model.py` / `validation-requirements.txt` | 开发验证：对照 ONNX Runtime 与 TensorRT 的数值输出 / Python 依赖清单 |
| `scripts/tests/menu-tests.ps1` | 开发验证：检查菜单路由、参数与进程身份处理 |

需要自动化或开发调试时，可以在项目根目录的 PowerShell 中执行：

```powershell
# 安装已固定版本并校验 SHA256 的本地依赖；已有依赖会复用
.\scripts\install.ps1

# 编译、核心回归测试，并部署到 dist/TestStudyYolo.exe
.\scripts\build.ps1

# 开启独立的检测窗口，默认不注入鼠标输入
.\scripts\start-preview.ps1
.\scripts\stop.ps1

# 查看物理显示器坐标；选择屏幕、采集模式和运行时限
.\scripts\run.ps1 --list-monitors
.\scripts\run.ps1 --capture dxgi --monitor 0 --headless --seconds 10
.\scripts\run.ps1 --capture gdi --monitor 0 --headless --seconds 10

# 离线图片 / 视频；此模式拒绝 --enable-input
.\scripts\run.ps1 --image workspace/inference/gril.jpg --label 1 --headless
.\scripts\run.ps1 --video your-test-video.mp4 --headless

# 测量桌面鼠标响应；保持鼠标不动，ESC 可以取消
.\scripts\run.ps1 --calibrate

# 在自己的测试窗口中启用输出；按住鼠标左键或右键才允许移动
.\scripts\run.ps1 --capture gdi --enable-input
```

热键：左方向键暂停，右方向键恢复，上方向键选择类别 1，下方向键选择类别 0。ESC、Ctrl+C、关闭预览窗口均执行取消、唤醒和线程回收；构建引擎时也支持取消。程序仅输出相对移动，不自动按下或释放鼠标按钮。

配置位于 **config/default.yml**。模型默认 **workspace/cf.onnx**，引擎缓存位于 **.local/engines**；缓存键包含模型 SHA256、TensorRT/CUDA/驱动版本、GPU 和精度。首次创建引擎可能需要数分钟。默认输出 **.local/runlogs** 下的帧日志、移动日志、统计与最后一帧；独立预览每次使用一个带时间的目录。

本机部署依赖项目下的 **.local** 目录，不能仅复制 exe 到其他电脑。安装脚本不更换显卡驱动，不下载或修改模型。该模型未随 Git 跟踪，新克隆需要自行准备相同结构的模型。程序验证输入为 float NCHW [batch,3,640,640]，解码输出为 [1,anchors,5+classes]，使用名字 images / output。

## 标定与结果解释

进程使用每显示器 DPI 感知，裁剪与目标偏移统一按物理像素计算；显示器可以有负坐标。标定文件只在 Windows 鼠标设置仍匹配时加载。主配置中的 X/Y 比例作为额外的应用灵敏度修正，乘以标定结果。

本机实测 X/Y 均为约 **0.762 输入单位/物理像素**，对应一次 16 单位试验；Windows 鼠标加速已开启，因此这只是局部估计。原始输入、锁定光标、相机 FOV、应用内灵敏度不能通过 Windows 光标标定自动推断，应在自己的测试场景中重新测量，不应把 DPI 倍率直接当作鼠标灵敏度。

模型有两个输出类别，但 ONNX 不包含类别名称。沿用了“0 对应身体、1 对应头部”的配置假设，需要用带标签的目标场景样本确认；数值一致性测试不能证明这个语义正确，也不能证明模型精度达到要求。
